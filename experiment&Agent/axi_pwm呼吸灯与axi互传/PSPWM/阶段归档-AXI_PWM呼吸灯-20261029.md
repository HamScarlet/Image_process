## 二、成品链路（as-built）

```
PS Cortex-A  (裸机 C, MMU/D-Cache 全关)
   │  *(volatile u32*)0x80200018 = ccr;      ← 写占空比，就这一条语句
   ▼
M_AXI_GP0  (64 bit, p2f_clk0 = 49.995 MHz)
   ▼
AXI_Matrix_0   DS2 命中 0x80200000，其余两路留给两个 AXI GPIO
   ▼
AXI_Protocol_Converter_2   AXI4 (64bit) → AXI4-Lite (32bit)
   ▼
axi_lite_pwm_0  ── S_AXI 从端（VERSION/CTRL/PSC/ARR/CCR/UPDATE 共 14 个寄存器）
   │
   ├─ pwm0_ccr_shadow ──(UPDATE 提交)──┐
   │                                   ▼
   │                        period_wrap 周期边界统一生效 → active_ccr
   │                                   ▼
   │                     period_count < active_ccr  → pwm_out[0]
   │                                   ▼
   └─────────────────────────────  T19  →  LED1 呼吸
                                   R19  →  LED2  (通道 1，已验证使能，未单独出灯测试)
                                   J15  →  LED3  (通道 2，同上)
                                   M20  →  LED4  ← CTRL[3] = motor_enable，常亮
   MIO51（纯 PS GPIO，不经 AXI）  →  LED5        ← 心跳/判据灯
```

**每一跳的实测证据**（缺一不可）：

| 观测 | 能证明什么 |
|---|---|
| LED5 常亮 | CPU 跑到 `main`、`VERSION` 读回正确、CCR 写回读自检通过 |
| LED4 常亮 | AXI4 写**真的落地**了，不是假 ACK —— `CTRL[3]` 有真实副作用 |
| LED1 呼吸 | PL 侧计数器/比较器 + 引脚约束都成立 |

## 三、地址映射与引脚（as-built）

### 地址

| 从端 | 基址 | 空间 | 来源 |
|---|---|---|---|
| `axi_lite_pwm` | `0x80200000` | 4 KB | `soc_prj/uisrc/01_rtl/system/system.address.xml` L31 |
| AXI GPIO 0 | `0x80000000` | 4 KB | 官方例程原有 |
| AXI GPIO 1 | `0x80100000` | 4 KB | 官方例程原有 |

> 主端 `ARM Processor System` 基址 `0x80000000`。三个从端各占 1 MB 槽位，互不重叠。

### 引脚（`fpga_pin.adc`，全部 `LVCMOS33` · BANK33）

| 信号 | 球号 | 板上丝印 | 极性 |
|---|---|---|---|
| `GPIO` | K14 | KEY1（inout，上拉） | 按下 = 0 |
| `GPIO_1` | J14 | KEY2（inout，上拉） | 按下 = 0 |
| `pwm_out[0]` | T19 | LED1 | **高 = 亮**（实测反推） |
| `pwm_out[1]` | R19 | LED2 | 高 = 亮 |
| `pwm_out[2]` | J15 | LED3 | 高 = 亮 |
| `motor_enable` | M20 | LED4 | 高 = 亮 |

> 球号对照取自 `AnLuRun\01_run_led\uisrc\04_pin\fpga_pin.adc`（官方 LED 例程），非推测。
> `motor_dir[1:0]` 在 `system_top.v` 里接了一根悬空 `wire`（Verilog 输出端口不能接 `2'b00` 常量）。接电机驱动板时改成 J12 的引脚即可。

### 寄存器（基址 `0x80200000`）

| 偏移 | 名称 | 读/写 | 说明 |
|---|---|---|---|
| `0x00` | `CTRL` | R/W | [0]/[1]/[2] 通道使能、[3] 电机使能 |
| `0x04` | `DIR` | R/W | [0]/[1] 电机方向（本期未引出） |
| `0x08` | `STATUS` | R | [2:0] 待提交标志、[5:3] 通道使能、[6] 电机使能 |
| `0x0C` | `VERSION` | R | 固定 `0x00010000` |
| `0x10/14/18` | `PWM0_PSC/ARR/CCR` | R/W | 通道 0 |
| `0x20/24/28` | `PWM1_PSC/ARR/CCR` | R/W | 通道 1 |
| `0x30/34/38` | `PWM2_PSC/ARR/CCR` | R/W | 通道 2 |
| `0x40` | `UPDATE` | W | 写 1 到 bit[n] 提交通道 n |

**频率公式与本期取值**：

```
f_pwm = 49,995,000 / ((PSC + 1) × (ARR + 1))
      = 49,995,000 / (1 × 10,000) = 4,999.5 Hz        (PSC=0, ARR=9999)
```

> 影子寄存器 + 周期边界提交：改占空比不会截断半个脉冲，电机换向/调速时不会产生窄脉冲毛刺。
> 电机场景建议 `ARR=2499`（19.998 kHz，超出人耳，无啸叫）。

## 六、验证方法：三通道互不依赖

本机串口长期不稳，所以**没有把串口当唯一判据**，改搭三条各自独立的观察通道：

| 通道 | 通路段 | 回答的问题 |
|---|---|---|
| LED5 = MIO51 | 纯 PS GPIO → MIO，绕开 AXI / PL / 串口 | CPU 跑起来了吗 |
| LED4 = M20 | AXI 写 → `CTRL[3]` → `motor_enable` | AXI 的"写"生效了吗 |
| LED1 = T19 | PL 计数器 → 比较器 → 引脚 | 波形出来了吗 |

**现象对照表**（排障时直接查这张表定位）：

| LED5 | LED4 | LED1 | 结论 |
|---|---|---|---|
| 慢闪不止 | 灭 | 灭 | `VERSION` 或写回读失败 → AXI 通路问题（PC 停在那一步） |
| 常亮 | 灭 | 灭 | 寄存器读写 OK，但 `CTRL` 没落到引脚 |
| 常亮 | 常亮 | 灭 | `CTRL` 生效，PWM 通道不出波 → 查通道使能位 / CCR |
| 常亮 | 常亮 | **呼吸** | **全通** |
| 完全不动 | 灭 | 灭 | 程序没跑到 `main` / 位流没下 / 时钟没起 |

**第三条兜底通道**：FD 调试器的 Memory 窗口直接读 `0x8020000C`，读到 `00010000` 即 AXI 通 —— **完全不依赖串口**。

`main.c` 里 `BRINGUP_STEP` 是分级开关，`=3` 才是完整呼吸灯：

| 值 | 行为 |
|---|---|
| 1 | 只读 `VERSION`，一个字节都不写（**最小探针**，用于怀疑 AXI 通路时） |
| 2 | 加 CCR 写回读自检 + 只开通道不出呼吸 |
| 3 | 完整：初始化 + 呼吸循环 |

> `=1` 时 5 个 LED 全灭是**正确现象**，不是故障 —— 因为一次 `CTRL` 都没写。

## 七、两个非 PWM 陷阱（会复发，必记）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | FD 编译 **72 errors，全在 `al_mpu.c`**（`AL_MPU_HalStruct` / `MPU_REGION_*` 未声明） | `soc_base/platform/inc/soc_plat.h` 里 15 行 `#define HAVE_*PS_DRIVER` 被 FD **重新导出 platform 时整块写空**，只剩占位符 `/*{{device}}*/`。而 `al_hal.h:41` 是 `#ifdef HAVE_MPUPS_DRIVER` 才 include `al_mpu_hal.h` | 补回 15 行。**判据**：`grep -c "^#define HAVE_" soc_plat.h` 应为 **15** |
| 2 | 串口无输出，但 elf 明明"编译成功" | 陈旧 `.o` 掩盖了 #1 —— `al_log.c` 里有 `#if !defined(HAVE_UARTPS_DRIVER) ... #error`，宏丢失后该文件处于"一编就报错"状态，从未被重编，elf 是靠旧目标文件拼出来的 | 修好头文件后**全量重编**。**判据**：`al_log.c.o` / `al_uart_hal.c.o` / `al_chip.c.o` 时间戳应当一致 |

> **陷阱 1 的复发条件说清楚**：不是"每次改代码"，而是**每次 FD 重新导出 platform / 重新生成 BSP 都会复发**。约定与之前「HPF 重新导出把 PS/PL 信息导丢」同一根因，都是 FD 的导出动作覆盖手写配置。
> **陷阱 2 的教训**：判断"编译成功"不能只看 `exit=0`，要看**目标文件时间戳是否跟着源文件走**。增量编译 + 头文件缺失 = 假成功。

> `timing.sdc` 的 4 条 Critical（USR-6001/8012/8159/6113）与官方模板**逐字节一致**，属模板噪声。
> ⚠️ `timing.sdc` 里 `create_clock -period 10` 对 49.995 MHz（≈20.002 ns）是 **2 倍过约束**。来自官方例程、既有工程一直这么跑，**本期故意不动**（避免引入新变量）。报告 `Report Clock Domain Luts` 里 `p2f_clk0` 显示 100 MHz 就是这个过约束的体现，不是真实频率。

**层次分解（值得记一笔）**：

| 实例 | logic lut | ripple | seq |
|---|---|---|---|
| `system_axi_lite_pwm_0`（PWM 本体） | 470 | 192 | 863 |
| ├ `u_pwm0` / `u_pwm1` / `u_pwm2` | 84 / 84 / 89 | 64 / 64 / 64 | 127 / 145 / 136 |
| `system_AXI_Protocol_Converter_2`（AXI4→Lite） | **530** | 42 | **1,400** |
