# 8/15 像素抽取降采样 · `rgb4_downscale_8_15` 数据处理流程

> 工程：`02-MIPI-CS500-HDMI(pl-ps)/1080p缩放为600p` ｜ 平台：DR1 + CS500(MIPI)
> 功能：把 **1920×1080 的 RGB 4 像素流，按 8/15 抽取降采样为 1024×576**，供后续装入 1024×600 帧（上下各 12 行黑边）
> 模块性质：**叶子模块**（无子实例、无 parameter、单时钟域）——本文以 3 张图拆开讲「抽取比例 / 打包握手 / 标记管理」

## 四、一句话总览

**想象一条 4 个像素并排跑的传送带：每 15 个像素里，扔 7 个、留 8 个；留下的重新凑成 4 个一拍送出去。横向这样抽，纵向也这样抽——于是 1920×1080 变成 1024×576。**

| 图 / 节 | 回答的问题 | 类比 |
|---|---|---|
| 图 1 + 第五节 | 一拍的 4 个像素**怎么被拆开、判、打包** | 分拣线：拆箱 → 过筛 → 重新装箱 |
| 图 2 | 比例**为什么正好是 8/15** | 一个 15 格的转盘，指针每走一格决定一次留/舍 |
| 图 3 + 第八节 | 什么时候**收数据、什么时候发数据、行尾帧头怎么标** | 红绿灯 + 一个"下批货带标签"的备忘条 |
| 第七节 | 时间基准与复位 | 全模块只有一个钟、一条复位线 |

> **一句话记住这个模块**：它是**纯像素抽取（decimation）**，不是插值也不是平均——**不模糊，但会有锯齿/摩尔纹**；代价极低，**不需要行缓存、不需要乘法器**，全部逻辑就是两个 4 bit 相位 + 一个 128 bit 打包寄存器。

## 五、逐阶段详解

本模块没有子实例，全部逻辑藏在**两段 always** 里：一段组合逻辑（`always @*`）算"下一拍的相位与打包结果"，一段时序逻辑（`always @(posedge I_clk ...)`）把它们锁进寄存器。

### 阶段 1：输入握手（`assign I_tready`）

| 项目 | 内容 |
|---|---|
| 表达式 | `assign I_tready = ~O_tvalid \| O_tready;` |
| 输出 | `I_tready`（注意：它是 **output**） |
| 干什么 | 输出寄存器空（`~O_tvalid`）或下游肯收（`O_tready`）时，就允许上游送新数据 |
| 为什么 | 这是 AXI-Stream 的标准"弹性缓冲"写法：**用输出寄存器当缓冲，一空就收**。因为输出速率只有输入的 8/15，这个寄存器还能顺手吸收节奏抖动 |

### 阶段 2：拆 4 车道（lane 0…3）

| 项目 | 内容 |
|---|---|
| 输入 | `I_tdata[127:0]`（128 bit = 4 像素 × 32 bit） |
| 输出 | 每次循环取一个像素的 24 bit：`[23:0]`、`[55:32]`、`[87:64]`、`[119:96]` |
| 干什么 | 把一拍里的 4 个像素依次取出，用 `for (lane = 0; lane < 4; lane = lane + 1)` 展开 |
| 为什么取 24 bit 而不是 32 bit | `isp_top` 送来的每像素 32 bit 里，真正有颜色的是低 24 bit（R8G8B8），高 8 bit 是空位。取 24 bit 就够了，**填回去时再补 0**，保持车道布局不变（下游 `uidbuf` 按 32 bit/像素理解，格式完全兼容） |

### 阶段 3：行级放行（`line_v_phase`）

| 项目 | 内容 |
|---|---|
| 输入 | `v_phase`（[3:0]）、`I_tuser` |
| 输出 | `line_v_phase = I_tuser ? 4'd7 : v_phase;` |
| 干什么 | 若 `line_v_phase >= 7` → **整行进入像素循环**；否则**整行一个像素都不处理** |
| 为什么用 `I_tuser` 强制置 7 | `I_tuser` 标记一帧的第一拍。置 7 保证**每一帧都从"保留"状态开始**，避免上一帧残留相位让首行被误丢 |

### 阶段 4：像素级抽取（`h_phase`）

| 项目 | 内容 |
|---|---|
| 输入 | `h_phase`（[3:0]） |
| 输出 | `h_phase_work`，以及"这个像素留不留" |
| 干什么 | `h_phase >= 7` → 保留，`h_phase -= 7`；否则跳过，`h_phase += 8` |
| 为什么 | 这一对步长让相位在 15 步内**遍历 0…14 各一次**，其中 ≥7 的 8 个留、<7 的 7 个舍 → 精确 8/15（详见第二节的轨迹图） |

> 这两级是**串联判定**：先判整行（纵向抽取），再判像素（横向抽取）。纵向被舍掉的行，连像素循环都不进，**省掉了 7/15 的无效计算**。

### 阶段 5：补齐为 32 bit

| 项目 | 内容 |
|---|---|
| 输入 | 24 bit 像素 |
| 输出 | `pixel_work = {8'd0, 24 bit}` |
| 干什么 | 高 8 位补 0，凑成 32 bit |
| 为什么 | 下游一直按"32 bit 一个像素"理解数据总线。补 0 后**车道布局与输入完全一致**，等于这个模块对数据格式"透明"，只改了像素个数 |

### 阶段 6：打包（`pack_data`）

| 项目 | 内容 |
|---|---|
| 输入 | 保留下来的像素（32 bit） |
| 输出 | `pack_data[127:0]`，按 `pack_count` 依次填 `[31:0]` → `[63:32]` → `[95:64]` → `[127:96]` |
| 干什么 | 把 4 个"散着来"的保留像素攒成完整一拍 |
| 为什么需要 | 输入是 4 像素/拍、输出也必须是 4 像素/拍，但保留像素是**不匀速**冒出来的（有时一拍留 3 个，有时留 1 个），所以必须攒够 4 个才能发 |

### 阶段 7：推出一拍（`scaled_push`）

| 项目 | 内容 |
|---|---|
| 输入 | 第 4 个像素填进 `pack_data` 的那一刻 |
| 输出 | `scaled_word = pack_data_work`、`scaled_push = 1'b1`、`pack_data`/`pack_count` 归零 |
| 干什么 | 组包完成的瞬间发出一个"推"信号 |
| 为什么一拍最多推一次 | 一拍只有 4 个像素，最多贡献 4 个保留像素 = 恰好 1 组。**不会出现"一拍攒出两组"**，所以单个 `scaled_push` 标志够用，不需要计数或 FIFO |

### 阶段 8：输出寄存器

| 项目 | 内容 |
|---|---|
| 装填 | `scaled_push` 时写入 `O_tdata = scaled_word`、`O_tlast = I_tlast`、`O_tuser = frame_start_pending \| I_tuser`、`O_tvalid = 1` |
| 清空 | `O_tvalid && O_tready` 时把 `O_tvalid` / `O_tlast` / `O_tuser` 全部清 0 |
| 干什么 | 把"不定速的推"变成标准的 AXI-Stream 有效/就绪握手 |
| 为什么标记要跟着清 | `tlast` / `tuser` 是**只在有效那一拍为高**的脉冲，不能常驻，否则下游会把每一拍都当成行尾/帧头 |

### 阶段 9：交给下游写通道

| 项目 | 内容 |
|---|---|
| 输出 | `scale_O_tdata[127:0]` / `tvalid` / `tlast` / `tuser` → `uidbuf` 写通道 |
| 下游怎么用 | `W_XSIZE = SCALED_IMAGE_WIDTH/4 = 256`（每行 256 拍）、`W_YSIZE = 576`（共 576 行） |
| 对得上吗 | 1024 像素 ÷ 4 像素/拍 = **256 拍** ✓；1080 行 × 8/15 = **576 行** ✓ |

## 六、数据变形总表

| 阶段 | 格式 | 每拍 / 每步携带 | 数量关系 |
|---|---|---|---|
| 输入 | RGB32 × 4 | 128 bit = 4 像素 | 每行 480 拍 |
| 拆车道 | 单像素 24 bit | 每拍 4 个 | 480 × 4 = 1920 像素 |
| 行列判定 | 单像素（保留 / 丢弃） | — | 每 15 留 8；整行每 15 留 8 |
| 补齐 | RGBA32 单像素 | 32 bit（高 8 位 = 0） | 保留数 1024 |
| 打包 | RGB32 × 4 | 128 bit | 每 4 个凑一拍 |
| 输出 | RGB32 × 4 | 128 bit | **每行 256 拍 / 每帧 576 行** |

> **最值得记住的一句话**：这个模块**没有改变"一拍几个像素"，也没有改变"一个像素几位"**——它只改变了"**一共多少个像素**"：横向 1920 → 1024，纵向 1080 → 576。

## 七、时钟与复位

| 项目 | 内容 |
|---|---|
| 时钟 | 只有 **1 个**：`I_clk`（顶层接 `S_hs_rx_clk`，来自 MIPI D-PHY 恢复的写侧时钟） |
| 复位 | 异步低有效：`negedge I_rst_n`（顶层接 `locked`，PLL 锁定才释放） |
| 复位初值 | `h_phase = 7`、`v_phase = 7`、`pack_count = 0`、`pack_data = 0`、`frame_start_pending = 1`、输出全 0 |
| 跨时钟域 | **无**。模块是纯单域逻辑，不引入任何 CDC 风险 |

> **为什么初值偏偏是 7 而不是 0**：因为抽取的"起跑相位"就是 7（见第二节轨迹）。复位值直接写成 7，就**保证复位后第一行第一像素的行为与稳态完全一致**，不会多留或少留一个像素。

## 八、行 / 帧标记管理

标记（`tlast` / `tuser`）是 AXI-Stream 里"这一包到哪结束、下一包从哪开始"的约定。本模块的做法：

| 标记 | 表达式 | 含义 | 兜底设计 |
|---|---|---|---|
| `O_tlast` | `<= I_tlast` | 行尾：随推出拍同步复制 | 依赖"每行最后一个 beat 恰好在打包边界"（见第三节 ⚠️） |
| `O_tuser` | `<= frame_start_pending \| I_tuser` | 帧头：复位后第一拍必带，之后由 `I_tuser` 触发 | **`frame_start_pending`**：若 `I_tuser` 那一拍没有输出（该 beat 的像素全被舍掉），标志**保留到下一次推出**，不会丢 |

**为什么帧头需要 pending 位而行尾不需要**：

- 帧头（`I_tuser`）出现在**第一拍的第一个像素**，而那时打包计数器是空的——**必须攒够 4 个像素才推得出**，所以一定会"延迟几拍"。用 pending 位把标记挂起，等下一拍推出时贴上。
- 行尾（`I_tlast`）出现在**最后一拍**，而本设计每行正好以"第 8 个保留像素"收尾（完整一组），**推出与行尾天然同步**。

## 九、其他细节与故障对照

| 细节 | 说明 |
|---|---|
| 硬件开销 | 相位 `h/v_phase` 4+4 bit、`pack_count` 2 bit、`pack_data` 128 bit、`scaled_word` 128 bit、`pixel_work` 32 bit、输出 `O_tdata` 128 bit + 3 个标志 ≈ **430 个触发器** |
| **无需行缓存** | 横向与纵向都是"丢"，不是"插值"，所以**一行一条流水线，不需要跨行存储**——这是本方案最大的成本优势 |
| 无需乘法器 / 无除法 | 全部是加减与比较，资源占用极小，时序压力可忽略 |
| 端口命名反了 | `I_tready` 是 **output**、`O_tready` 是 **input**，与本工程"`I_` = 输入、`O_` = 输出"的约定相反（顶层 `ISP_O_tready` 同样反着）。功能正确，**读代码时注意别看名字** |
| `pixel_work` 的用法 | 用模块级 `reg [31:0]` 当循环临时变量，靠"赋值后立即使用"的顺序语义工作。`for` 展开后等价于局部临时变量，功能正确；**若日后改写成不可综合风格或加流水，需要留意** |
| `scaled_word` 与 `pack_data_work` | 二者在推出一拍时是同一个值，`scaled_word` 属冗余中间变量。不影响功能，可省 |
| 未使用的位宽 | `pack_data` 每个 32 bit 车道的高 8 bit 恒为 0（因为像素只补了 24 bit）。**实际传的是 RGB24，占着 RGB32 的位宽** |
| 拉平设计 | 全模块无状态机、无握手等待，**单拍 combin 逻辑 + 单级输出寄存器**，延迟最短 |

**故障对照表**：

| 现象 | 首先怀疑 |
|---|---|
| 图像右侧出现重复列 / 竖条纹 | `h_phase` 未在 `I_tlast` 时复位成 7，导致每行起跑相位漂移 |
| 图像出现横向拉丝 / 上下半帧错位 | `v_phase` 未在 `I_tuser` 时复位；或 `line_v_phase` 判定把不该留的行留下了 |
| 画面出现规律性竖条（莫尔纹） | **正常现象**——纯抽取降采样的固有代价，不是 bug。需要抑制只能换插值/均值算法 |
| 画面被横向压扁或拉伸 | 横向保留数 ≠ 1024（检查源宽是否为 15 的整数倍） |
| 下游整屏错位、行不同步 | `O_tlast` 丢标记——检查"每行最后一个 beat 是否落在打包边界"（见第三节 ⚠️） |
| 首帧缺帧头导致画面偏移一格 | `frame_start_pending` 复位值被改成 0（应为 1） |
| 输出卡死、上游被反压 | `I_tready` 逻辑被改动，或下游 `O_tready` 长期为 0（DDR 写通道堵塞） |
| 只出一部分图像就停 | `pack_count` 在第 4 个像素时未归零，导致后续分组错位 |

## 十、参数一览

| 名称 | 值 | 推导 / 含义 |
|---|---|---|
| `h_phase` / `v_phase` | `[3:0]`，复位值 **7** | 相位寄存器，有效范围 0…14（15 个状态，4 bit 够用） |
| 保留步长 | **−7** | `phase >= 7` 时保留，`phase -= 7` |
| 跳过步长 | **+8** | `phase < 7` 时跳过，`phase += 8` |
| 循环周期 | **15 像素 / 15 行** | 减 7 与加 8 互补，构成 15 步闭环 |
| 每周期保留 | **8** | = 15 − 7 |
| 横向比例 | **8/15 ≈ 0.5333** | 1920 × 8/15 = **1024** |
| 纵向比例 | **8/15** | 1080 × 8/15 = **576** |
| `pack_count` | `[1:0]`，复位值 0 | 0 → 1 → 2 → 3 → 0 循环，满 4 推出 |
| 输入拍 / 行 | **480** | 1920 ÷ 4 |
| 输出拍 / 行 | **256** | 1024 ÷ 4（= `uidbuf.W_XSIZE`） |
| 输入行数 | **1080** | |
| 输出行数 | **576** | = `uidbuf.W_YSIZE` |
| 输出寄存器级数 | **1** | `O_tdata` + `O_tvalid/O_tlast/O_tuser` |
| 参数 / 子实例 | **无** | 比例写死在代码里（−7 / +8），**改比例必须改代码** |

## 十一、总结

1. **功能**：纯像素抽取降采样，1920×1080 → 1024×576，横向与纵向同为 **8/15**。
2. **原理**：一个 4 bit 相位在 15 步内遍历 0…14，相位 ≥7 的 8 个保留、<7 的 7 个跳过；`−7` / `+8` 是为凑出这个 15 步闭环专门选的步长。
3. **格式**：一拍 4 像素进、一拍 4 像素出，**位宽与车道布局完全不变**，只少了像素——对上下游是"透明"的。
4. **关键约束**：源尺寸必须是 **15 的整数倍**（1920 = 15×128、1080 = 15×72），否则每行保留数不齐，且 `O_tlast` 可能丢失。
5. **成本**：无行缓存、无乘法器、无状态机，约 430 个触发器 + 单级输出寄存器——**用极小的面积换 8/15 的整帧缩放**，代价是抽取式降采样固有的锯齿与莫尔纹。

## 附：原代码 · `rgb4_downscale_8_15`（未做任何删改）

> 源文件：`1080p缩放为600p/1080pto600p/soc_prj/uisrc/01_rtl/my_image_process/rgb4_downscale_8_15.v`
> 逐字附于下方，便于与文中参数逐项对照核验。

```verilog
module rgb4_downscale_8_15 (
    input  wire         I_clk,
    input  wire         I_rst_n,
    input  wire [127:0] I_tdata,
    input  wire         I_tlast,
    input  wire         I_tuser,
    input  wire         I_tvalid,
    output wire         I_tready,
    output reg  [127:0] O_tdata,
    output reg          O_tlast,
    output reg          O_tuser,
    output reg          O_tvalid,
    input  wire         O_tready
);

    reg [3:0] h_phase;
    reg [3:0] v_phase;
    reg [1:0] pack_count;
    reg [127:0] pack_data;
    reg frame_start_pending;

    reg [3:0] h_phase_next;
    reg [3:0] v_phase_next;
    reg [1:0] pack_count_next;
    reg [127:0] pack_data_next;
    reg [127:0] scaled_word;
    reg scaled_push;
    reg [3:0] line_v_phase;
    reg [3:0] h_phase_work;
    reg [1:0] pack_count_work;
    reg [127:0] pack_data_work;
    reg [31:0] pixel_work;
    integer lane;

    assign I_tready = ~O_tvalid | O_tready;

    always @* begin
        h_phase_next = h_phase;
        v_phase_next = v_phase;
        pack_count_next = pack_count;
        pack_data_next = pack_data;
        scaled_word = 128'd0;
        scaled_push = 1'b0;
        line_v_phase = I_tuser ? 4'd7 : v_phase;
        h_phase_work = I_tuser ? 4'd7 : h_phase;
        pack_count_work = I_tuser ? 2'd0 : pack_count;
        pack_data_work = I_tuser ? 128'd0 : pack_data;
        pixel_work = 32'd0;

        if (I_tvalid && I_tready) begin
            if (line_v_phase >= 4'd7) begin
                for (lane = 0; lane < 4; lane = lane + 1) begin
                    if (h_phase_work >= 4'd7) begin
                        h_phase_work = h_phase_work - 4'd7;
                        case (lane)
                            0: pixel_work = {8'd0, I_tdata[23:0]};
                            1: pixel_work = {8'd0, I_tdata[55:32]};
                            2: pixel_work = {8'd0, I_tdata[87:64]};
                            default: pixel_work = {8'd0, I_tdata[119:96]};
                        endcase

                        case (pack_count_work)
                            0: begin
                                pack_data_work[31:0] = pixel_work;
                                pack_count_work = 2'd1;
                            end
                            1: begin
                                pack_data_work[63:32] = pixel_work;
                                pack_count_work = 2'd2;
                            end
                            2: begin
                                pack_data_work[95:64] = pixel_work;
                                pack_count_work = 2'd3;
                            end
                            default: begin
                                pack_data_work[127:96] = pixel_work;
                                scaled_word = pack_data_work;
                                scaled_push = 1'b1;
                                pack_data_work = 128'd0;
                                pack_count_work = 2'd0;
                            end
                        endcase
                    end else begin
                        h_phase_work = h_phase_work + 4'd8;
                    end
                end
            end

            h_phase_next = h_phase_work;
            pack_count_next = pack_count_work;
            pack_data_next = pack_data_work;
            if (I_tuser)
                v_phase_next = 4'd7;

            if (I_tlast) begin
                h_phase_next = 4'd7;
                pack_count_next = 2'd0;
                pack_data_next = 128'd0;
                if (line_v_phase >= 4'd7)
                    v_phase_next = line_v_phase - 4'd7;
                else
                    v_phase_next = line_v_phase + 4'd8;
            end
        end
    end

    always @(posedge I_clk or negedge I_rst_n) begin
        if (!I_rst_n) begin
            h_phase <= 4'd7;
            v_phase <= 4'd7;
            pack_count <= 2'd0;
            pack_data <= 128'd0;
            frame_start_pending <= 1'b1;
            O_tdata <= 128'd0;
            O_tlast <= 1'b0;
            O_tuser <= 1'b0;
            O_tvalid <= 1'b0;
        end else begin
            // Keep line/frame markers aligned with valid data, and clear them
            // when the output beat is consumed.
            if (O_tvalid && O_tready) begin
                O_tvalid <= 1'b0;
                O_tlast <= 1'b0;
                O_tuser <= 1'b0;
            end

            if (I_tvalid && I_tready) begin
                h_phase <= h_phase_next;
                v_phase <= v_phase_next;
                pack_count <= pack_count_next;
                pack_data <= pack_data_next;

                if (I_tuser)
                    frame_start_pending <= 1'b1;

                if (scaled_push) begin
                    O_tdata <= scaled_word;
                    O_tlast <= I_tlast;
                    O_tuser <= frame_start_pending | I_tuser;
                    O_tvalid <= 1'b1;
                    if (frame_start_pending | I_tuser)
                        frame_start_pending <= 1'b0;
                end
            end
        end
    end

endmodule
```
