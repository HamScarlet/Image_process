## 一、定位

ISP 在视频链路中的位置：

```
sensor(SC500CS) → MIPI D-PHY RX → CSI 解包 → RAW10 解包 → uial2axis
                └→ 【ISP】→ rgb4_downscale_8_15 → uidbuf(写 DDR)
                                              → uidbuf(读) → uivtc → HDMI TX
```

ISP 的全部职责：**把 sensor 的 Bayer RAW10 转成可显示的 RGB888，并做"调味"（白平衡、伽马、反差、饱和）**。它不含缩放、不含锐化、不含降噪。

## 二、位宽与格式地图

这条链路的"数据形态"每级都在变，调参前先记清这张表。

| 级 | 模块 | 位宽 | 每拍像素数 | 格式 |
|---|---|---|---|---|
| 输入 | `uial2axis` | 40 bit | 4 | 4×RAW10（Bayer） |
| 1 | `BLC` | 40 bit | 4 | 4×RAW10 |
| 2 | `raw_matrix_3x3_buffer` | 40 bit ×3 行 | 4 | 3×3 Bayer 邻域 |
| 3 | `bilinear_interpolation` | **128 bit** | 4 | 4×{8'b0,R8,G8,B8} |
| 4 | `data128_96` | **96 bit** | 4 | 4×{R8,G8,B8} |
| 5 | `awb` | 96 bit | 4 | 同上 |
| 6 | `image_cut` | 96 bit | 4 | 同上 |
| 7 | `gamma` | 96 bit | 4 | 同上 |
| 8 | `contrast_adj` | 96 bit | 4 | 同上 |
| 9 | `Brightness_adjustment` | 96 bit | 4 | 同上 |
| 10 | `Saturation_adj` | 96 bit | 4 | 同上 |
| 输出 | `data96_128` | **128 bit** | 4 | 4×{8'b0,R8,G8,B8} → `uidbuf.I_W_tdata` |

- `data128_96` 是纯位拼接：`{I[119:96], I[87:64], I[55:32], I[23:0]}`（`data128_96.v:16`）——128 bit 里每 32 bit 只用低 24 bit，丢掉高 8 bit。
- `data96_128` 反向补零，是为了对上 `uidbuf` 的 `W_DATAWIDTH(128)`。
- 链路**全程 4 像素/拍**，所有模块都是 4 路并行（`genvar i = 0..3`），所以各级**天然同步、无需额外对齐 FIFO**。

## 三、逐级详解

### 3.1 BLC — 黑电平校正

**原理.** sensor 的光电二极管在完全无光时输出并非 0，而是由暗电流与偏置决定的"光学黑电平"。不扣掉它，画面会整体抬起来、黑位发灰、动态范围被白扔。BLC 是 ISP 的第一级，必须在去马赛克之前做。

**RTL.** `BLC/blc.v`

```verilog
data_out[i] <= I_blc_data[i] - black_level_offset[i];   // L64
if (负数) data_out[i] <= 10'd0;                          // L67  负值钳 0
```

**参数.** `Black_level_offset_r0..r3`（`isp_top.v:96~99`），单位 = **RAW10 的 1 LSB（0~1023）**，4 路独立。

| 项 | 值 |
|---|---|
| 模块默认（`blc.v:12~15`） | 15 |
| 本工程现值 | **65** |
| SC500CS 典型光学黑电平 | ≈ 64（10 bit 下） |

**应用建议.**
- 现值 65 基本合理，**不要盲调**。
- **症状 → 方向**：画面像蒙了一层纱、黑的东西不黑、暗部没有层次 → 偏小，试 **72~80**；暗部死黑、阴影里什么都没有 → 偏大，试 **56~60**。
- 判据：遮住镜头看画面，应接近纯黑但不"发亮"；黑电平扣多了会在暗部出现**明显的色块/紫边**（因为 R/G/B 暗电流不同，4 路 offset 可分别微调）。

---

### 3.2 3×3 矩阵 + 双线性去马赛克

**原理.** Bayer 阵列每个像素只有一个颜色分量（BGGR 排列：偶行 R G R G…／奇行 G B G B…）。要得到每个像素的完整 RGB，必须用邻域插值补出缺失的两个分量。`raw_matrix_3x3_buffer` 负责把串行流变成 3×3 窗口（当前行/上一行/下一行 + Bayer 行相位 `bayer_ypos`），`bilinear_interpolation` 负责按窗口算权重。

**RTL.** `raw_matrix_3x3_buffer`（`isp_top.v:118`）+ `bilinear_interpolation`（`isp_top.v:140`）

**参数.** `BAYER_MODE`（`bilinear_interpolation.v:31`），支持 `"BGGR" / "GBRG" / "RGGB" / "GRBG"` 四分支（L168/L336/L507/L680）。

| 项 | 值 |
|---|---|
| 本工程现值 | **`"BGGR"`** |

**应用建议.**
- **此参数只有对错，没有大小**：填错的表现是**红蓝互换（人脸发蓝、天空发橙）**，而不是"不清晰"。
- SC500CS 若是 BGGR 就保持不动。若日后换 sensor，先确认它的 Bayer 相位再改这一个参数。
- 双线性是**最廉价的去马赛克**，在细密纹理（栅栏、条纹衣服）上会产生**伪彩/拉链纹**。想改善只能换算法（如 Malvar-He-Cutler 5×5），代价是乘法器与行缓存，本工程不划算。

---

### 3.3 AWB — 自动白平衡

**原理.** "灰度世界"假设：一幅自然场景中 R/G/B 的平均值应趋于相等。用整帧统计求出 R、B 相对 G 的增益，再把每个像素的 R、B 乘上增益，G 不动。

**RTL.** `awb/awb.v`

```verilog
divider div_gen_G_R_r1 ( ... .quotient(dout_R[i]) );   // L202  求 G/R
divider divide_G_B_r1  ( ... .quotient(dout_B[i]) );   // L212  求 G/B
in_r_r1 <= in_r_x1[19:0];                              // L267  Q4.16，0x10000 = 1.0
if (|in_r_x1[47:20]) in_r_r1 <= 20'hfffff;             // L264  上限 ≈ 16.0
R_new_r1 <= in_r_r1 * rgb888_r_d1[0];                  // L403
B_new_r1 <= in_b_r1 * rgb888_b_d1[0];                  // L405
```

**参数.** `IMG_WIDTH` / `IMG_HEIGHT`（`isp_top.v:166~167`）——只影响统计窗口，必须与真实分辨率一致。

| 项 | 值 |
|---|---|
| 本工程现值 | 1920 / 1080（与 `system.v` 的 `IMG_*` 同源） |

**应用建议.**
- **无需手调**，但它是"颜色正不正"的主因：画面整体偏黄/偏蓝先怀疑 AWB 统计窗口不对（`IMG_*` 与真实帧尺寸不符会导致统计跨帧、增益乱跳 → **画面颜色周期性漂移**）。
- 已知局限：灰度世界在**单色场景**（大片绿色草地、大片蓝天）下会失效——它会"强行"把绿色场景拉成灰。这是算法本身的锅，不是参数问题。
- 增益上限 16.0（L264），极端偏色场景会顶到上限后仍偏色。

---

### 3.4 image_cut — 边缘涂黑

**原理.** 去马赛克在图像最外圈没有足够的邻域数据，输出不可信。`image_cut` 把最外圈的像素**替换成 0**。

**RTL.** `image_cut/image_cut.v` —— 注意它**不是裁掉像素**：

```verilog
localparam IMG_WIDTH_4x = (IMG_WIDTH >> 2);              // L51  h_cnt 以 4 像素为一组
wire w_skip = (v_cnt < SKIP_ROWS_top) || (h_cnt < SKIP_COLS_left) ||
              (v_cnt >= IMG_HEIGHT - SKIP_ROWS_bottom) ||
              (h_cnt >= IMG_WIDTH_4x - SKIP_COLS_right); // L53
O_tdata <= w_skip ? {DATA_WIDTH{1'b0}} : I_tdata_r;      // L60  涂黑
assign O_tlast = I_tlast_r1;  assign O_tuser = I_tuser_r1;// L95~96 时序直通
```

⇒ **像素总数、tlast/tuser 位置都不变**，只是把指定区域的像素值清零。

**参数.** `SKIP_ROWS_top / SKIP_ROWS_bottom / SKIP_COLS_left / SKIP_COLS_right`（`isp_top.v:187~190`），单位 = **4 像素宽的组**（因为一拍 4 像素）。

| 项 | 本工程现值 | 等效像素 |
|---|---|---|
| `SKIP_ROWS_top` | 0 | 0 行 |
| `SKIP_ROWS_bottom` | 0 | 0 行 |
| `SKIP_COLS_left` | **1** | **最左 4 列被涂黑** |
| `SKIP_COLS_right` | 0 | 0 列 |
| 模块默认（`image_cut.v:24~27`） | 2 / 2 / 2 / 2 | 上下左右各 2 组 |

**应用建议.**
- 现配置**不对称**：只有左边 4 列是黑的，右边没处理。屏幕上表现为**画面最左侧一条固定黑边**（在 1024 宽上约 2 像素，放大看才明显）。
- 想干净 → 四处全改 `0`（前提是已确认去马赛克的边缘输出可接受，否则会出现左侧彩边）。
- 想彻底稳 → 四处都改 `1`（左右各黑 4 列、上下各黑 4 行），画面会被均匀切掉 4 像素边框，观感最"正"。
- ⚠️ 本模块**不能**用来缩放或裁剪构图：它只涂黑、不改尺寸。要"看更大视场"必须改 sensor 开窗或加降采样（见 [[8-15像素抽取降采样图形化链路]]）。

### 3.5 gamma — 伽马校正（对"清晰感"影响最大的两级之一）

**原理.** sensor 输出与物理光强成正比（线性），而人眼与显示器的传递特性是幂律，标准显示编码为 γ≈2.2。这一级把线性信号**编码**为显示信号。曲线本身是非线性的，所以它同时决定"中间调亮度"和"暗部层次"。

**RTL.** `gamma/gamma.v` + 9 张查找表 `lut_0_8.v … lut_2_6.v`

- 每张 LUT 都是 `case` 形式的 256 项表。实测拟合（以 `lut_2_2.v` 校验）：

$$
\text{out}_{12} = 4095 \times \left(\frac{\text{in}+0.5}{255.5}\right)^{1/\gamma}
$$

- 输出截位（`gamma.v:469`）：`acc_rgb888_r_x2 <= (x1[20]) ? 8'd255 : x1[19:12]` ⇒ **溢出饱和到 255，不回绕**。

**参数.** `GAMMA_10x`（`gamma.v:20`，`isp_top.v:207`），= γ 的 10 倍。

| `GAMMA_10x` | 8 | 12 | 14 | 16 | **18** | 20 | **22（现值）** | 24 | 26 |
|---|---|---|---|---|---|---|---|---|---|
| γ | 0.8 | 1.2 | 1.4 | 1.6 | 1.8 | 2.0 | **2.2** | 2.4 | 2.6 |
| LUT 实测 out（in=20） | 174 | — | — | — | 996 | — | **1300** | — | 1553 |
| LUT 实测 out（in=128） | 1730 | — | — | — | 2784 | — | **2994** | — | 3143 |
| LUT 实测 out（in=255） | 4086 | — | — | — | 4091 | — | **4092** | — | 4092 |

**方向（由实测数据确定，勿凭直觉）：γ 越大 → 中间调越亮、越"平"；γ 越小 → 越暗、越"硬"。**

**应用建议.**
- **γ = 2.2 是标准显示编码值，是正确基线**（因为输入是线性 RAW）。别为了"更亮"长期偏离它——真正该动的是 brightness / contrast。
- **场景偏暗、想看清暗部细节（室内、夜间、阴影里的车牌/行人）** → 试 **24~26**：中间调整体抬起。代价是画面"发飘"、反差变弱，用 contrast 补回来。
- **想要"通透、硬朗、有质感"** → 试 **20 甚至 18**：反差增强，但暗部会被压死。
- 一次只改一格（±2），否则无法归因。

### 3.6 contrast_adj — 对比度（本链路唯一"不动亮度只加反差"的旋钮）

**原理.** 以 128 为中心做斜率放大，暗的更暗、亮的更亮，**中灰不动**。这是提升"清晰感"最安全的手段，因为它不改变亮度、不裁动态范围（在未饱和区间内）。

**RTL.** `contrast_adj/contrast_adj.v`

```verilog
pixel_shifted_R[i] <= {8'd0, rgb888_r[i]} - 16'd128;          // L103  绕中灰
temp_value_R[i]    <= (pixel_shifted_R[i] * contrast_level)>>7; // L116  Q0.7
R_d[i]             <= temp_value_R[i] + 16'd128;              // L129
assign R[i] = (R_d[i][9]) ? 0 : (R_d[i][8]) ? 255 : R_d[i][7:0];// L135 饱和钳位
```

**参数.** `contrast_level`（`contrast_adj.v:19`，`isp_top.v:224`）

| 值 | 128 | 140 | 160 | 180 | 200 |
|---|---|---|---|---|---|
| 倍率 | 1.00× | **1.094×（现值）** | 1.25× | 1.41× | 1.56× |

模块默认 160。

**应用建议.**
- **推荐 155~165**。这是"看起来更清楚"性价比最高的一档，代价只是暗部/亮部略微收窄。
- **不要超过 180**：一旦斜率过大，暗部与亮部的像素会撞到钳位（0 / 255），**细节反而丢失**，表现为"黑成一片、白成一片"。
- 与 gamma 联动：gamma 调大（变亮变平）后，**必须**把 contrast 相应调大，否则画面会显得灰而无力。
- 判断是否过头：看画面中**最暗与最亮区域的纹理是否还在**。

### 3.7 Brightness_adjustment — 亮度

==🔴PL 按键控制曝光，靠近总开关的第一个按键为降低曝光，第二个为提升

**原理.** 对 R/G/B 各加同一个常数 = 整体平移。不改对比度，但**会单方向截断动态范围**。

**RTL.** `brightness_adj/Brightness_adjustment.v`

```verilog
R_d[i] <= rgb888_r[i] + BRIGHTNESS_ADD - BRIGHTNESS_MINUS;    // L90
assign R[i] = (R_d[i][9]) ? 0 : (R_d[i][8]) ? 255 : R_d[i][7:0]; // L96  饱和钳位
```

⇒ 净效果 `out = in + ADD − MINUS`，结果钳在 `[0,255]`。

**参数.** `BRIGHTNESS_ADD` / `BRIGHTNESS_MINUS`（`isp_top.v:241~242`）

| 项 | 值 |
|---|---|
| 本工程现值 | `ADD = 0`、`MINUS = 20` ⇒ **每像素 −20** |
| `Brightness_adjustment.v:19` 的模块默认 | `ADD = 20`、`MINUS = 0` |

> ⚠️ **模块头里的 `parameter` 是死参数。** 实例化时显式传了值，默认值永远不生效——改 `Brightness_adjustment.v:19` 不会有任何画面变化，必须改 `isp_top.v:241~242`。

**应用建议.**
- **当前 −20 是纯亏损**：白扔 8% 动态范围，且 `in < 20` 的像素被直接钳成 0（暗部细节归零）。**建议先改成 `0 / 0`**，这一条改动零风险、见效立即。
- 需要略提亮 → `ADD = 10~20`、`MINUS = 0`。
- **不要用它替代 gamma**：平移对暗部是"减法式"的（先压掉），对大范围提亮应优先动 gamma。
- 调参记录：历代工程（`1600_900pfirstsuccess` / `1600_900p2ndsuccess` / `mymipi_hdmi1`）**全都是 `0/20`**，不是本次移植引入的差异。

### 3.8 Saturation_adj — 饱和度

**原理.** 在亮度 Y 不变的前提下，把颜色往"更艳"或"更灰"的方向拉。公式为经典 `R_new = -Y·value + R·(1+value)`。

**RTL.** `saturation_adj/Saturation_adj.v`

```verilog
parameter [8:0] ADJUST_VAL = 128                       // L26  9 bit 二进制补码
parameter C0 = 9'd306, C1 = 10'd601, C2 = 7'd117;      // L136~138  0.299/0.587/0.114 × 1024
Y[i]        <= Y_w[i][17:10];                          // L175  加权求亮度
RGB_C[i]    <= 255 + adjust_val[i];                    // L161
Y_m[i]      <= Y[i]*Y_C_abs[i];                        // L189
rgb888_r_r2[i] <= rgb888_r_r1[i]*RGB_C[i];             // L190
R_new[i] <= Y_R_m_s[i][18] ? 0 : Y_R_m_s[i][17:16] > 0 ? 255 : Y_R_m_s[i][15:8]; // L211
```

化简：`out = [R·(255+adj) − Y·adj] >> 8`。

**参数.** `ADJUST_VAL`（`saturation_adj.v:26`，`isp_top.v:259`），**9 bit 二进制补码，取值 −256 ~ +255**。

| `ADJUST_VAL` | 0 | 64 | 128 | **130（现值）** | 192 | 255 | −255 |
|---|---|---|---|---|---|---|---|
| 效果 | **中性** | +25% | +50% | **+51%** | +75% | +100% | ≈ 全灰 |

> ⚠️ **源码注释"默认值为128"具有误导性：中性点是 `0`，不是 128。** 验算：`adj=0` 时 `out = 255R/256 ≈ R`（不动）；`adj=130` 时 `out = 1.496R − 0.5Y = R + 0.5(R−Y)`，即 **+51% 饱和度**。
> 模块内部用 9 bit 截断实现负数：`RGB_C = 255 + adj`，`adj = −128` 时 9 bit 截断得 127 ⇒ `0.496R`，逻辑自洽。

**应用建议.**
- **现值 130 已经偏高（+51%）。**
- **追求"干净、通透"应往下调** → 试 **80~110**。过饱和会带来伪色、彩噪被放大、边缘出现彩色镶边，**视觉上更花更糊、反而更不清晰**。
- 追求"浓艳"才往上调，但**建议不超过 160**；到 200 以上一定会出现伪彩。
- 与 AWB 联动：AWB 没做好的偏色**不要**用饱和度去掩盖，会变成彩色噪点。

### 3.9 data128_96 / data96_128 — 格式桥接

**原理.** 上游去马赛克按 32 bit/像素（含 8 bit 填充）组织数据，下游需要一个连通的 24 bit/像素 表示，最后再补回 32 bit 去匹配 `uidbuf` 的 128 bit 写端口。

**RTL.**

```verilog
// data128_96.v:16
assign O_tdata = {I_tdata[119:96], I_tdata[87:64], I_tdata[55:32], I_tdata[23:0]};
```

**参数.** 无。

**应用建议.**
- 纯位操作，无参数可调。
- 唯一需要记住的是：**这些"填充 8 bit"不能参与任何算术**（它们是 0，不是有效数据），否则会算错。新增 ISP 级时务必按 96 bit（4×24）接口接入。

| BLC | `Black_level_offset_r0..r3` | `isp_top.v:96~99` | 65 | `raw − offset`，负钳 0；发灰↓、死黑↑ | 有症状再动，试 72~80 或 56~60 |

| image_cut | `SKIP_ROWS_*/SKIP_COLS_*` | `isp_top.v:187~190` | 0/0/**1**/0 | **涂黑**（不改尺寸）；单位=4 像素组 | 想干净 → 改 0/0/0/0 |
| gamma | `GAMMA_10x` | `isp_top.v:207` | **22** | γ 越大越亮越平 | 偏暗 → **24~26**；要硬朗 → 20 |
| contrast | `contrast_level` | `isp_top.v:224` | **140** | Q0.7，128=1.0× | **→ 155~165** |
| brightness | `ADD` / `MINUS` | `isp_top.v:241~242` | **0 / 20** | 整体 −20，暗部切 0 | **→ 0 / 0**（第一优先） |
| saturation | `ADJUST_VAL` | `isp_top.v:259` | **130** | 9bit 补码，**0=中性**；130=+51% | **→ 80~110**（现值偏高） |

## 五、建议的调参顺序

一次只改一步，改完必须重新综合上板看效果，否则无法归因。

1. **`brightness` → `0 / 0`**（零风险，立刻消除"灰糊"）
2. **`contrast_level` → 160**（"更清楚"的主力旋钮）
3. **`GAMMA_10x` → 24**（若场景偏暗，这一步暗部细节提升最明显）
4. **`ADJUST_VAL` → 100**（画面会立刻变"干净"）
5. **`Black_level_offset` → 72**（只在前四步仍"发纱"时才试）

**每步判据（用同一场景、同一光照比对）**：

| 观察点 | 期望 |
|---|---|
| 黑位 | 暗部有层次但不发亮；不出现紫/绿色块 |
| 高光 | 亮部（天空、反光）仍有纹理，不是一片死白 |
| 中间调 | 主体（车道线、车牌、人）轮廓可辨 |
| 颜色 | 灰/白物体不带明显色偏 |
| 伪彩 | 细节密集处（栅栏、网格）不应出现彩虹色斑 |

## 六、症状 → 对策

| 症状 | 首查 | 次查 |
|---|---|---|
| 整体发灰、像蒙了纱 | `brightness` 是否负数（现值 −20） | `Black_level_offset` 偏小 |
| 暗部一片黑、无细节 | `Black_level_offset` 偏大 | `contrast_level` 过大（>180） |
| 亮部一片白、无层次 | `contrast_level` 过大 | `GAMMA_10x` 过大 |
| 画面偏黄 / 偏蓝 | AWB 的 `IMG_*` 是否与真实分辨率一致 | sensor 侧白平衡寄存器 |
| 人脸发蓝、天空发橙 | `BAYER_MODE` 填错 | — |
| 边缘彩色镶边、彩噪明显 | `ADJUST_VAL` 过大（>160） | `contrast_level` 过大 |
| 画面"花、糊、看不清" | **不是 ISP 参数**，见第七节 | — |

## 七、能力边界 —— 这套 ISP 做不到什么

`uisrc/03_ip/isp/` 下只有 10 个模块：`BLC`、`raw_matrix_3x3_buffer`、`bilinear_interpolation`、`data128_96`、`awb`、`image_cut`、`gamma`、`contrast_adj`、`brightness_adj`、`saturation_adj`、`data96_128`。

**没有锐化（边缘增强）、没有降噪、没有缩放。** 因此：

1. **"画面不够清晰"不可能靠上述参数根治。** 参数的极限是"把已有的细节显出来"，不能"创造细节"。上面所有调整只能在**观感层面**改善，不改变有效信息量。
2. **当前下游 8/15 抽取本身是"丢点"，不是低通降采样**（见 [[8-15像素抽取降采样图形化链路]]）——细密纹理会混叠成摩尔纹、边缘出现锯齿，这才是"看不清"的直接元凶。要真正改善须把抽取换成**区域平均（盒式滤波，即采样点及其邻域参与运算）**，代价是行缓存。
3. **想要边缘更利落，必须新增一级 3×3 高通 / 非锐化掩模（unsharp mask）**，接在 `saturation_adj` 之后或 `bilinear_interpolation` 之前均可（前者在 RGB 域、实现简单，后者更接近 sensor 原始分辨率）。
4. **去噪与锐化天然矛盾**：这套链路连降噪都没有，所以高感光下的噪声会**原样进入降采样再被放大**——若新增锐化，必须同时考虑加一级轻量去噪（中值或双边），否则噪点会被锐化得更明显。

**结论：先修数据通路（1 bit 截断 → 见 [[移植尝试记录]] 第 4 节），再谈调参；调参到顶后，瓶颈一定回到"8/15 丢点抽取 + 无锐化"这两件事上。**
