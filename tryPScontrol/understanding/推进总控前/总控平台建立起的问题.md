# 总控平台建立起的问题（PS 侧稳定性风险清单）

> 对象：`mipiHDMIbySD` 稳定平台 · PS 侧 `soc_sdk`（FSBL + BSP + `fdma_en` 应用）
> 依据：`soc_sdk` 全量**只读**勘察 + 编译产物（`fdma_en.map` / `fdma_en.elf`）交叉验证；每条结论都能指回文件与行号
> 性质：**问题梳理与规划，未做任何改动**

**一句话结论**：平台"能跑"，但**没有任何运行时自我保护**。真正的风险不是"某个零件会坏"，而是**坏了没人知道，也没人能救**。

---

## 一、总体判断

| 维度 | 现状 |
|---|---|
| 平台初始化 | FSBL 一次性配完（时钟 / DDR / MIO / UART），应用**完全继承**，自身不做任何校验 |
| 错误上报 | `Soc_PlatInit()` 与 `fd_ddr_init()` 的返回值**双双被丢弃** → DDR 训练失败也不上报 |
| 对 PL 的控制 | 只有 `p2f_rst0_n`（GP0/GP1 未使能；`pl_gpio` 宏虽勾选，但 RTL 里三线全断，不可用） |
| 对 PL 的观测 | **无**（无 GP 通道、无中断、无健康寄存器） |
| 自动恢复 | **无**（看门狗实际未启用，卡死无人复位） |
| 唯一故障反馈 | **人眼看 HDMI 屏幕** |

一句话概括当前架构：**PS 对 PL 只推不改、只听不见**——能下达指令，拿不到任何状态回报。

---

## 二、先排除的误判（已核实，避免走弯路）

以下 6 项是排查时容易怀疑、但**经源码与产物验证不成立**的：

| 曾经的怀疑 | 结论 | 证据 |
|---|---|---|
| MMU / D-cache 没配好，DDR 属性错 | **正常** | 从 ELF 直读页表：`MMUTableL0[0] = 0x8013003` 是**表描述符**（非块描述符）→ `DDR_2M_MAPPING` 生效，DDR 按 2 MB 粒度可控；`MMUTableL1[0] = 0x705` = `NORM_CACHE`，属性正确 |
| `SUPPORT_NONSECURE` 未定义 → BSS 没清、GIC / 定时器未初始化 | **正常** | 本平台跑 EL3，而 `SUPPORT_NONSECURE` 仅在 `ARMv8_EL=EL1` 时定义（`tools/make/armv8-a.inc:57`）。非该分支下 `main_entry` 会 `bl clear_bss`（`al_aarch64_start.S:349`），且 `AlChip_Dr1m90Init()` 执行 `AlGic_Init() + AlSys_StartTimer()`（`al_dr1m90.c:22-25`） |
| `disable_mmu()` 只清 SCTLR 的 M/C 位、不刷 cache → Handoff 丢数据 | **无实际危害** | `alfsbl_handoff.c:63` 在它**之前**已调 `AlCache_DisableDCache()`，其内部先 `__asm_flush_dcache_all()`（`al_aarch64_core.c:44-48`） |
| 串口日志链路可能断（`Allog` 未初始化 → 静默丢日志） | **正常** | `components_init() → AlLog_Init()` 在 `bl main` 之前执行（`al_chip.c:60` / `al_aarch64_start.S:361`）；`LOG_DEV=AL_LOG_UART1`（`tools/make/config.mk:95,105`） |
| FSBL 出错没做处理 | **有处理** | 四阶段每个 `FsblStatus` 都判（`alfsbl_main.c:44-135`），出错走 `AlFsbl_PrintErrorMessage + AlFsbl_ErrorLockDown` |
| 内存放不下 | **有富余** | `.stack` @`0x089F8000` 共 6.03 MB；heap ≈ 8.9 MB；`.rt_text` / `.rt_data` 均为 **0 字节**（map 实测） |

## 三、问题清单

### P0-1｜平台初始化的错误码全被丢弃（最该先堵）

```c
fsbl/alfsbl_main.c:36                   Soc_PlatInit();   /* 返回值没有接 */
soc_base/platform/src/soc_plat.c:1861   fd_ddr_init();    /* 返回值没有接 */
```

`fd_ddr_init()` 内部明明 `return err`（`fd_ddr_init.c:19-52`），上层却丢掉了。

| 项 | 内容 |
|---|---|
| 后果链 | DDR 训练失败 / 参数不符 → FSBL **毫不知情**继续 → 把应用加载进 DDR 并跳过去 → 随机死机、花屏、黑屏，而**日志看起来一切正常** |
| 触发条件 | DDR 颗粒批次差异、VREF / ODT / 驱动强度边际、温度漂移 |
| 为什么重要 | 这是"**闪一下 → 全黑**"的有力候选机理之一（另一个候选在 PL 侧 `PLL → fifowait → VTC` 链） |
| 验证方法 | ① 串口是否稳定出现 `[DDR INFO] Available Capacity 1024 MB`；② 冷启动 N 次看是否偶发失败；③ 把返回值打出来 |
| 缓解 | 把 `err` 打出来并在非 0 时报警（**只加读，不改逻辑**） |

### P0-2｜应用没有平台自检，100% 继承 FSBL 状态

全仓 grep：`Soc_PlatInit()` 只被 `fsbl/alfsbl_main.c:36` 调用；应用的 `main()` 只有 `Fclk_Init()` + printf。

| 项 | 内容 |
|---|---|
| 后果 | FSBL 半途失败 → 应用照样跑；JTAG 单独加载应用 → 时钟 / DDR 全没配，行为不可预期 |
| 现有可用抓手 | FSBL 会把状态写进 `SYSCTRL_S_FSBL_ERR_CODE`：运行中 `0xFFFF`、成功 `0x0`、失败写错误码（`alfsbl_hw.h:21,22,297`、`alfsbl_handoff.c:89`、`alfsbl_err_lockdown.c:29`） |
| 寄存器地址 | `SYSCTRL_S_BASEADDR(0xF8806000) + 0x184` = **`0xF8806184`** |
| 低成本堵法 | 应用开头读一次 `0xF8806184` 并打印。**一个寄存器即可补上"FSBL 是否成功"的盲区** |
| 现状 | 应用从未读过该寄存器（grep 无命中） |

### P0-3｜对 PL 零可观测（结构性，见第四节图）

GP0/GP1 主从全未使能 + 全部中断未使能 + 无看门狗 → PL 侧任何异常（PLL 失锁、MIPI 无信号、时序违例）系统**无法发现、无法记录、无法恢复**。

### P1-1｜DDR 带宽 / 延迟竞争，PS 侧无 QoS 配置

| 项 | 内容 |
|---|---|
| 事实 | `Design.xml` 中 HP0 的 `arqos` / `awqos` 是**外部端口**（由 PL 主设备驱动），PS 侧没有任何 QoS 配置寄存器；`Slave_AXI_HP0_DATA_WIDTH=64`（`Design.xml:37-38,636,713`） |
| 量级 | 1920×1080×4 B×60 fps ≈ **497 MB/s**；DDR3-1333 × 32 bit 峰值 ≈ 5.33 GB/s → **平均带宽够，风险在突发抢占** |
| 机理 | PL 一发起长突发，CPU 的取指 / 栈 / printf 数据同样要过 DDR → 延迟尖峰 |
| 缓解 | 限源（PL 侧节流，属 PL 范围）；或调整 PL 主设备发出的 QoS 值 |

### P1-2｜`main()` 返回后的行为，与现有注释里的假说不符

| 项 | 内容 |
|---|---|
| 源码事实 | `al_aarch64_start.S` 中 `bl main` 之后是 `bl __libc_fini_array` → **`b .` 死等**；`exit()` / `_exit()` 也是 `while(1)`（`lib/newlib/gcc/exit.c`） |
| 推论 | **源码里不存在"返回即复位"的路径**，因此注释里"return 会被 C 运行时复位、把 `p2f_rst_n` 重新拉低"的假说**在源码上不成立** |
| 影响 | "闪一下 → 全黑"的根因需另找（P0-1 的 DDR 是一条候选，PL 侧复位链是另一条） |
| 处置 | 保活循环可以留着（无害），但**不要把它当作已证实的结论**去排障 |

### P1-3｜缓存一致性（潜在风险，非现症）

| 项 | 内容 |
|---|---|
| 事实 | DDR 全段（含 PL 帧缓存 `0x0A000000`）映射为 `NORM_CACHE` |
| 现状 | 应用当前不读帧缓存 → **今天不触发** |
| 未来触发点 | 一旦 PS 要读帧缓存（做算法 / 传网 / 校验），**必读脏数据** |
| 好消息 | ① `DDR_2M_MAPPING` 已开 → 可按 2 MB 粒度改属性；② `.noncacheable` 段机制可用（当前尺寸 0）；③ 本构建下 `AlCache_SetMemoryAttr()` **真正生效**（不是 `#else return AL_OK` 那个静默空分支，`al_aarch64_core.c:110-125`） |
| 约束 | 地址必须 **2 MB 对齐**，且只能改 `mmu_2m_list` 覆盖的区段 |

### P1-4｜启动失败回滚可能变成无限重启环

`AlFsbl_ErrorLockDown`（`alfsbl_err_lockdown.c:47-60`）在非 JTAG 模式下会 `MULTI_BOOT += 1` 并触发全局软复位，让 BootROM 换下一个镜像。

| 项 | 内容 |
|---|---|
| 风险 | 若 SD 卡上只有一个镜像 / 镜像本身损坏 → **无限重启** |
| 现象 | 串口打印"同样的日志反复重来"，极易被误判为"系统不稳定" |
| 排查 | **先数串口日志是否在重复**；再确认镜像分区顺序为 P0=FSBL → P1=PL 码流 → 应用最后 |

### P2-1｜保活循环纯忙等，CPU 100% 空转

`AlSys_MDelay` 实现是读 `cntpct_el0` 自旋，**无 `wfi`、无中断**（`al_sys_timer.c:71`）。`while(1){ AlSys_MDelay(1000); printf(...); }` 等于让核心永久满负荷。

影响：24/7 运行的功耗与温升（A35 @1 GHz 影响有限），但会**放大 P1-1 的 DDR 竞争**。
缓解：改为 `wfi` 等待 + 仅在状态变化时打印。

### P2-2｜延时基准未经实测 ⚠️ 待确认

| 项 | 内容 |
|---|---|
| 事实 | `CNTFRQ_EL0` 由软件写入 `SystemCoreClock`（`al_aarch64_start.S:267-270`），其值 = `SYSTEM_CLOCK = 33333333`（`soc_plat.h:88`）；`AlSys_GetTimerFreq()` 直接返回它（`al_sys_timer.c:36-37`） |
| 判断 | **逻辑自洽**，但硬件计数器实际输入时钟无法从源码确认 |
| 零成本验证 | 用现有日志量墙钟——两条 `[loop]` 之间应**恰好 1.000 s**。若实测约 1.33 s → 实际时钟 25 MHz，**所有延时差 33%** |
| 影响面 | DDR 训练等待、MMC 超时、以及所有"延时后取样"的调试结论 |

### P2-3｜无 ECC、栈无保护、无热监控

| 项 | 内容 |
|---|---|
| DDR 无 ECC | `DDRC_ECC_EN = NONE` → 位翻转静默污染，视频帧最先受害 |
| 栈无保护 | 6 MB 栈与 heap **直接相邻**（`_heap_end = ADDR(.stack) - 64`，`gcc_dr1m90_ddr_aarch64.ld:313-315`）→ 栈溢出静默踩 heap，无 guard page |
| 无热 / 压监控 | BSP 里没有温度或电压监控驱动 |

### P2-4｜同一组寄存器被四处操作（交叉点）

`0xF8800080` / `0xF8801078` / `0xF8806330` 三个寄存器被以下**四处**代码反复读写：

| # | 位置 | 操作 |
|---|---|---|
| 1 | `ps_pl_0` 配置表（FSBL `Soc_PlatInit`） | `0xF8801078[0] = 1`（释放 HP0 复位） |
| 2 | `AlTop_GPPortEnable()`（`al_top.c:29-40`） | `0xF8800080 &= ~0x3`；`0xF8801078` 清 `0x33` → 延时 1 ms → 置 `0x33` |
| 3 | `Soc_PsPlInit()`（Handoff 前，`alfsbl_handoff.c:101`） | 重配 ps_pl |
| 4 | `Fclk_Init()`（应用 `main.c:46`） | 同一套动作**又做一遍** |

寄存器基址（`al_hwcfg.h:217-221`）：`TOP_NS = 0xF8800000`、`TOP_CRP = 0xF8801000`、`TOP_SYSCNT_S = 0xF8804000`、`TOP_S = 0xF8806000`。

**顺带发现一个维护性问题**：平台**本有**正式接口 `AlTop_P2F_RstAssert(Index)` / `AlTop_P2F_RstRelease(Index)`（`al_top.c:44-66`），而应用的 `Fclk_Init()` 用**裸地址魔数**手工实现，绕过了 HAL。改硬件时极易漏改。

### P2-5｜配置生成物不同步风险

`soc_plat.h`、7 张操作码表、`Design.xml` 全是 hpfTool 生成物（`HPF_EXPORT_TIME 2026/10/05 17:20:34`）。改了 PL / HPF 但忘记重新导出 → **PS 行为不变**。

另有双开关陷阱：`*PS_ENABLE`（是否配置外设）与 `HAVE_*_DRIVER`（是否编译驱动）是两回事。实测不一致的例子：`HAVE_IICPS_DRIVER` 已定义，但 `I2C0PS_ENABLE` / `I2C1PS_ENABLE` 都是注释状态 → **驱动编进来了、外设却没配**。

### P2-6｜FSBL 镜像余量小

`fsbl.bin` = 207,488 B，OCM 区 252 KB（`0x3F000`）→ 余量约 **44 KB**。FSBL 再加功能要留意链接失败。

**读图口诀**：左边 PS、右边 PL，中间三条横线就是两者之间**全部**的物理连接。**只有最上面一条实线是通的**（复位 + 时钟）；下面两条虚线都是"设计里留了、硬件上没通"——第二条是 `pl_gpio`（三线全断：`pl_gpio_out` 悬空、`pl_gpio_oe` 空连接、`pl_gpio_in` 接常量 0），第三条是 GP 通道与中断（配置里未使能）。它们本可以让 PS 读写 PL 寄存器、让 PL 中断 PS，现在两条全断，所以 **PS 只能推、不能听**。

## 五、现场排障速查

| 现象 | 首先怀疑 |
|---|---|
| 串口一行都没有 | 接错口（**必须 UART1 = Type-C**，`0xF8401000` @115200）；或 FSBL 没起来 |
| 串口日志**反复重来** | 启动回滚成环（P1-4）：`MULTI_BOOT` 递增 + 软复位，检查 SD 镜像分区顺序 |
| 日志停在 `Stage Err` | 看错误码（`AlFsbl_PrintErrorMessage`），并读 `0xF8806184` 复核 |
| 有 banner、HDMI 全黑 | 先看 `[RESULT] p2f_rst_n[3:0]` 是否 `F`；是 `F` 则问题在 PL 侧（PLL / fifowait / VTC） |
| **偶发**花屏 / 黑屏 / 死机 | P0-1：DDR 训练边际性。查 `[DDR INFO]` 是否稳定、冷启动多次复现 |
| 程序跑一会儿卡死 | **没有看门狗兜底**，只能外部复位 |
| 想用 PS 读 PL 寄存器 | **当前做不到**（GP0/GP1 未使能，`pl_gpio` 又三线全断），只能让 PL 写进 DDR 再由 PS 去读 |
| 改了硬件但 PS 行为没变 | 忘了重新导出 HPF 并重编（`soc_plat.h` 与 7 张表都是生成物） |

## 六、处置规划（全部只动 PS 侧，不碰 PL）

| 阶段 | 目标 | 动作 | 验证判据 |
|---|---|---|---|
| **0** | 把"不可观测"变成"可观测"（只加读，不改逻辑） | ① `main` 开头读 `0xF8806184` 并打印；② 打印 `Soc_PlatInit` / `fd_ddr_init` 的返回值 | 串口出现 `[FSBL] code = 0`；DDR 错误能显式暴露 |
| **1** | 验证延时基准 | 用现有日志量墙钟：两条 `[loop]` 间隔 | 1.000 s ±1% |
| **2** | DDR 边际性压力 | 冷启动 N 次 + 长时间运行，记录 `[DDR INFO]` | 无偶发失败 |
| **3** | 缓存一致性预案（**等真要 PS 读帧缓存时再做**） | 把帧缓存区划进 `.noncacheable`，或用 `AlCache_FlushDcacheRange` | 读到的数据与 PL 写入一致 |
| **4** | 决定恢复策略 | 是否启用 WDT（`ALFSBL_WDT_EXCLUDE` 与 `AlFsbl_InitWdt()` 目前都被注释）；是否在 PL 侧开 P2F 中断 | 卡死能被自动复位 |

**建议从阶段 0 开始**：投入最小、收益最大——它把 P0-1、P0-2、P1-2 三条从"猜"变成"看得见"。
